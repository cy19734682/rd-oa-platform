# 主系统 + 子系统改版方案（v2 修订：窗口级分离）

> 版本：v2.0（待评审） · 2026-10-22 · 替代 v1.0 中「壳内切换」为「窗口级分离」
> 触发：v1 四批实现完成并实测后，产品负责人反馈两点——① 主系统首页去掉「我的待办」，布局优化为更简约的 OA 风首页；② 主/子系统分离不彻底，子系统需**新窗口打开**且每个子系统可拥有**独立样式**

---

## 1. 背景与修订点

v1 已落地「主系统门户 + 子系统壳」：门户为卡片网格入口，子系统经 header 身份切换在**同一窗口内**进入。实测后确认两点修订：

| # | 反馈 | v1 现状 | v2 目标 |
|---|------|---------|---------|
| 1 | 首页去掉待办，要 OA 风、简约 | 双面板（待办｜公告）占底部，信息密度偏高 | 去掉待办面板；公告改通栏列表；hero 增加统计胶囊，整体更接近主流 OA 门户首页 |
| 2 | 分离不彻底 | 子系统壳内切换：同窗口、同文档、仅 header 换身份 | 子系统**独立 HTML 入口 + 独立 CSS + 新窗口打开**；形式上是一个独立站点，底层仍同项目、同登录态、同数据层 |

**修订后的目标架构：一主四子，窗口级分离。**

---

## 2. 目标架构

### 2.1 页面拓扑

```
主系统 index.html（门户 + 系统管理 + 登录 + 全局搜索）
   ├─ 点击内部子系统卡 / 常用应用 / 搜索结果进入 ─→ window.open 新窗口
   │     ├─ subs/proj.html   （项目管理子系统：独立 URL / 独立样式）
   │     ├─ subs/dev.html    （研发公共子系统）
   │     ├─ subs/asset.html  （过程资产子系统）
   │     └─ subs/perf.html   （绩效管理子系统）
   └─ 点击外部系统卡 ────────────→ window.open 第三方系统（不变）
```

- **子系统入口形态**：每个内部子系统一个**薄 HTML 文件**（约 20 行：骨架 + 该子系统需要的脚本子集 + 专属 CSS `<link>`）。形式上是独立站点，未来可单独打包部署；底层共享 `js/modules/` 下的代码与 localStorage 数据。
- **样式独立**：每个子系统一个 `css/subs/<key>.css`，在共享 `css/style.css` **之后**加载，覆写 CSS 变量（`--primary` / `--bg` / 圆角 / 卡片风格等）与局部组件。四个子系统分别沿用各自板块主题色（proj 蓝 / dev 绿 / asset 青 / perf 紫），并在卡片、按钮、磁贴上做出可感知的差异。
- **登录态**：localStorage 同源共享，子系统窗口天然带登录态；未登录打开子系统页 → 显示「请先登录」引导（点击回主系统登录页），登录后回到该子系统。
- **路由持久化**：按窗口隔离——主系统 `sessionStorage["oa_route"]` 只存门户态；每个子系统窗口用独立 key `sessionStorage["oa_route::<app>"]`，各自记住自己的二级/三级页面，互不污染。
- **返回主系统**：子系统 header 左侧「← 返回主系统」按钮——若本窗口由主门户打开（`window.opener` 存活）则聚焦 opener；否则新开主门户标签。面包屑一级「主系统」可点击同样回门户。

### 2.2 主系统首页新布局（去待办 · OA 简约风）

自上而下：

1. **hero 主标题区**（白卡三段式）：主标题「研发 OA 平台」+ 英文副标题 + 描述；右侧操作区「🔄 刷新」+「⚙️ 系统管理」（仅管理员）；标题下方新增**统计胶囊**（如「4 个业务系统 · 3 个外部链接 · N 项待办铃铛」——只放计数，不放列表）
2. **问候语条**（无卡片背景，现状保留）
3. **🚪 业务子系统卡网格**（现状保留，点击改新窗口）
4. **🔗 外部系统卡网格**（现状保留）
5. **🧭 我的常用应用**（现状保留，点击改新窗口）
6. **📢 通知公告**：由「待办｜公告」双面板改为**通栏公告列表卡**（置顶优先，展示最新 4~5 条，未读红点），占满内容宽度的单卡

- **去掉**：`_portalTodoPanel()`（待办面板）不再渲染
- **保留**：右上角 🔔 铃铛（全局待办入口，与首页面板同源；铃铛是跨模块功能，子系统窗口同样可用——如也想去掉请告知）

### 2.3 壳代码处置（views-shell.js / router.js）

| v1 组件 | v2 处置 |
|---|---|
| `applyShellChrome / exitShellChrome / syncShellChrome`（主窗口内 header 换身份） | 主系统不再进壳，三函数从主链路移除；`views-shell.js` 改造成**子系统页 header 渲染器**：渲染子系统图标+名称、「← 返回主系统」按钮、`body.in-subsystem`（子系统窗口整站浅灰底视觉隔离仍保留） |
| `enterSubsystem(appKey)`（壳内进入） | 改为 `openSubsystem(appKey)`：校验权限后 `window.open('subs/<key>.html')` |
| `backToPortal()`（壳内回门户） | 改为回主门户：`opener.focus()` 或 `window.open(index.html)` |
| `curApp` / `_isSubsystemKey` / saveRoute 的 `app` 字段 | 子系统窗口内仍用 `curApp` 标识「我在哪个子系统」（用于 header 渲染与路由 key），主门户恒为空 |
| `restoreRoute` 旧结构兼容 | 子系统窗口读 `oa_route::<app>`；无记录进该子系统首页；主门户读 `oa_route`，无 app 字段直接渲染门户 |

### 2.4 全链路入口窗口化

| 入口 | v1 行为 | v2 行为 |
|---|---|---|
| 门户内部子系统卡 | `enterSubsystem(mod)` 壳内进入 | `window.open('subs/<mod>.html')` |
| 门户外部系统卡 | `window.open(url)` | 不变 |
| 常用应用磁贴（内部项） | `openFavApp(app,mod,sub)` 壳内进入 | `window.open('subs/<app>.html?m=<mod>&v=<sub>')`，子系统窗口启动时落到指定二级页 |
| 常用应用磁贴（外部项） | `window.open(url)` | 不变 |
| 全局搜索结果「进入」按钮 | 壳内进入 | `window.open(subs/...?m&v)` 同 fav |
| 铃铛待办条目跳转 | 壳内进入 | 新窗口落到对应子系统页面 |
| 子系统内二级/三级导航 | 同窗口 renderCurrent | **不变**（子系统内部仍是单页导航） |
| 系统管理 | 主系统内 selectModule('sys') | 不变（系统管理留在主系统，符合 v1 定位） |

### 2.5 权限与登录校验（子系统窗口启动时）

```
打开 subs/<app>.html
  → 未登录（localStorage 无 session）→ 渲染「请先登录」引导卡 → 点击回 index.html 登录
  → 已登录但 canAccessModule(app) = false → 渲染「无权访问该子系统」提示卡（联系管理员）
  → 正常 → 按 ?m&v 参数或 oa_route::<app> 或默认首页渲染
```

### 3.3 兼容性

- 旧 `sessionStorage["oa_route"]`（v1 壳态 `{app,m,v,ss,s}`）：主门户读取时忽略 app 直接渲染门户；子系统窗口只用 `oa_route::<app>`，无兼容负担
- fav 数据 `{app,mod,sub}`：v2 已就绪，仅打开行为变化
- 菜单种子 / perms / 数据层：零改动
- 外部系统外链卡：零改动

## 5. 待决策点

1. **子系统入口形态**：A. 每子系统独立 HTML 文件（推荐：URL/样式/窗口全独立，未来可单独部署）；B. 单一 `subsystem.html` + `?app=` 参数（文件少一个，但「独立」程度低一档）
2. **子系统「返回主系统」行为**：A. opener 存活则聚焦原门户标签，否则新开（推荐）；B. 恒定新开主门户标签
3. **子系统窗口内是否保留全局搜索框与 🔔 铃铛**：A. 保留（推荐：壳共享，待办/搜索是跨模块能力）；B. 精简掉，只留时钟与头像
4. **通知公告在首页的形态**：A. 通栏单卡列表（推荐，简约）；B. 与「我的常用应用」并列双栏；C. 只留最新 3 条摘要条
