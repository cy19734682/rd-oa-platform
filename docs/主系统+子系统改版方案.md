# 主系统 + 子系统改版方案

> 版本：v1.0（待评审） · 2026-10-22 · 基于提交 `6e4a506`

---

## 1. 背景与目标

当前平台是单壳多板块结构：登录后进入「工作台」，通过板块磁贴进入 5 大板块（项目管理 / 研发公共 / 过程资产 / 绩效管理 / 系统管理），各板块以磁铺式导航展开二级、三级菜单。

**改版目标**：将平台重构为 **主系统 + 子系统** 形态：

- **主系统**：承担两件事 —— ① 各子系统的统一入口（入口页参考展会「燃气工作助手」的智能体卡片网格风格，做浅色化适配）；② 保留原「系统管理」模块
- **子系统**：项目管理、研发公共、过程资产、绩效管理升级为四个形式上独立的子系统，进入后有自己的顶栏、面包屑与返回主系统通道，视觉上与主系统门户隔离
- **底层不变**：仍然是一个项目、一套登录态、一套数据层（localStorage）、一套权限体系 —— 子系统只是「壳内切换」，不拆 iframe、不建多页面

## 2. 现状架构盘点（代码事实，全部已核实）

| 维度 | 现状 |
|---|---|
| 应用骨架 | `index.html`：`#app` = header（logo / 全局搜索 / 时钟 / 铃铛 / 头像）+ body（`#crumb` + `#content`）；登录页 `#view-login` 独立 |
| 路由 | 三级态：`curModule`（板块）/ `curView`（二级）/ `curSubSub`（三级）；`goHome / selectModule / selectSub / selectSubSub`；持久化 `sessionStorage["oa_route"] = {m,v,ss,s}` |
| 模块树 | `DEFAULT_MODULES` 6 个顶层 key：home（工作台）/ proj（项目管理，4 子，含 2 外链）/ dev（研发公共，3 子，含 1 外链）/ asset（过程资产，4 子）/ perf（绩效，4 二级含 1 个三级父节点）/ sys（系统管理，7 子） |
| 视图层 | `VIEWS` 注册表 20 个视图（home / std* / ec* / pa* / sys*）；板块首页 `renderModuleHome`（磁贴 6~8 列）、三级分组页 `renderSubGroupHome`、工作台 `renderHome`（问候语 + 板块磁贴 + fav + 待办/公告双面板） |
| 外部系统 | 已有 `type:"external" + url` 机制（pms / board / 自动化测试平台 3 个），点击 `window.open` 新窗口 |
| 权限 | `hasRole(module, ...keys)` 递归授权至任意深度；`ROLE_EXTRA_ACTIONS` 角色叠加；菜单种子指纹同步（旧结构自动迁移）；`permschange` 事件驱动刷新 |
| 数据 | localStorage 持久化 10 类数据（menus / roles / accounts / depts / assets / pa / std / ec / notices / session）；**改版数据层零改动** |
| 验证体系 | 七套回归（smoke 直跑 + 6 个生成器脚本需跑 `.gen.js`）+ `compare.js` 快照 diff + 功能探针 + 基线管理 |

**关键结论**：现有「板块」概念与「子系统」几乎同构（模块树 / 权限 / 磁贴导航全都有），改版主要是**新增门户层与子系统壳层**，业务视图零改动。

## 4. 三个核心设计

### 4.1 主系统门户（入口页）

参考展会「燃气工作助手」项目页的卡片网格，做**浅色化适配**（企业 OA 主场景保持浅色，见决策点 5）：

| 展会原件 | 门户适配 |
|---|---|
| 深蓝黑底 + 玻璃卡片 | 浅灰白页面底 + 白卡 + 1px 浅边框 + 极淡阴影（无真实模糊，保性能） |
| 图标底座 40px 圆角渐变蓝底白符号 | 同构：`--primary` 渐变底 + 白色符号（磁贴 emoji 升级为图标容器） |
| 状态胶囊（青绿描边弱底） | 同构：运行正常 / 维护中 / 外部系统 三种语义胶囊 |
| 字段网格（label 上值下） | 卡内嵌「模块数 / 负责人 / 更新日期」三格 |
| 「进入系统 →」文字操作链 | 卡片整卡点击 + 右下「进入系统 →」文字链双入口 |
| 标题三段式（中文 + 英文 + 描述） | 「研发 OA 平台 · 子系统门户 / SUBSYSTEM PORTAL / 一句话描述」 |

**页面结构**：
1. 顶部标题区（三段式）+ 右上「系统管理」按钮（`sysAdmin` 可见，跳转现有 sys 板块）
2. 问候语条（紧凑单行：头像 + 问候 + 角色）
3. 内部子系统卡片网格（4 列自适应，间距 18px）
4. 外部子系统卡片网格（同构，带「外部系统」胶囊，点击新窗口）
5. 待办 / 公告双面板（现有组件复用，挪至门户底部）
6. fav 常用应用区保留（升级为「子系统 / 页面」两级，见 4.3）

### 4.2 子系统壳（形式独立的关键）

**采用「壳内切换」而非 iframe**。理由：原型是单项目无构建；iframe 会破坏 toast / modal / 权限 / 搜索体系，并要求维护双份 HTML 骨架与 SSO 传递，代价与收益不成比例。壳内切换保留了单页应用全部优势，且未来若子系统要独立部署，只需把渲染目标换成 `iframe.src`，迁移路径平滑。

进入子系统后发生四件事：

1. **顶栏切换**：左侧 logo 区替换为「子系统图标 + 子系统名」，其后紧跟「← 返回主系统」按钮；右侧（搜索 / 时钟 / 铃铛 / 头像）保持不变
2. **面包屑改级**：`主系统 / 绩效管理 / 互评管理`（一级从「工作台」变为「主系统」，二级为子系统名）
3. **内容区视觉隔离**：`body` 挂 `in-subsystem` class，切换一套 CSS 变量（页面底 / 卡片底微差），不改变组件结构
4. **路由态扩展**：新增 `curApp`（子系统 key），`goHome()` 语义改为「回主系统门户」

**子系统内导航维持现状磁贴式**（一级磁贴 → 二级页面 → 三级分组），不引入左侧导航 —— 与全平台导航模型一致，改版风险最小（如后续想要侧导航形态，见决策点 1）。

### 4.3 管理适配与全局功能

| 功能 | 改版处理 |
|---|---|
| 菜单管理（sysMenu） | 拆为两个视图：**门户配置**（子系统上架 / 排序 / 图标 / 描述 / 可见角色）+ **子系统内菜单**（现有三级树原样保留） |
| 角色权限（sysRole） | 子系统级授权沿用现有模块级 `canAccessModule`；门户配置增加「门户可见角色」字段 |
| fav 常用应用 | 结构 `{mod,sub}` → `{app,mod,sub}`；旧数据缺 `app` 时按 `mod` 反查归属子系统，自动补全 |
| 全局搜索 | 保留在主系统顶栏，跨子系统内容索引（现有 SEARCH 范围不变，入口不随壳切换消失） |
| 待办 / 公告 | 主系统级服务，只在门户展示；子系统内通过铃铛/入口跳回门户查看 |
| 外部子系统 | `type:"external"` 的 3 个菜单项从 proj / dev 板块内**迁出**为门户级外链卡（决策点 3），板块内不再重复出现 |

## 6. 数据与兼容性

| 项 | 处理 |
|---|---|
| `oa_route` | `{m,v,ss,s}` → `{app,m,v,ss,s}`；恢复时缺 `app` 且 `m` 为子系统 key → 自动补 `app`（按子系统反查） |
| `oa_menus` | 种子指纹同步机制复用：新增 `subsystem` 标记与门户种子变更触发一次全量同步（旧平铺/嵌套结构自动迁移，机制已在 round 31/32 验证） |
| fav 数据 | `{mod,sub}` → 自动补 `app` 字段；无法归属的旧项过滤回退默认 |
| perms | 角色 perms 结构不变（模块 → 二级 → 三级），子系统即模块级授权 |
| 快照基线 | 预期差异：`renders.home` hash 变（门户重写）、`renders.sysMenu` hash 变（双 tab）、`menus` 结构增 subsystem 标记、`windowKeys` 新增壳层函数（控制在 ~6 个） |

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 门户重写导致 `renders.home` 基线大diff | 预期内，逐项解释；探针覆盖关键结构 |
| 旧路由/旧菜单数据不兼容 | 指纹同步 + 反查补全双机制；批次 1 探针专测「旧 sessionStorage 直接恢复」 |
| 「形式独立」程度不及预期（仍是磁贴内页） | 壳层四件套（header / 面包屑 / 变量 / 返回）已提供视觉隔离；若仍嫌弱，决策点 1 可升级侧导航 |
| 外部系统迁出后原板块变空（proj 剩 2 项 / dev 剩 2 项） | 属预期收敛：门户即唯一入口层；板块首页保留作为子系统内页 |
| 搜索/待办归属混乱 | 明确：搜索全局（顶栏常驻）、待办公告主系统级（门户展示） |

## 9. 待决策点（确认后进入实现）

1. **子系统内导航形态**：维持磁贴式（推荐，风险最小）/ 改左侧导航（更贴近展会独立系统形态）/ 混合
2. **系统管理入口位置**：门户右上按钮（推荐）/ 门户内一张特殊卡 / 顶部独立 tab
3. **外部系统是否迁出板块**：迁出为门户级外链卡（推荐，避免双入口）/ 保留在板块内
4. **待办/公告是否留门户**：保留（推荐）/ 移入铃铛下拉
5. **门户明暗**：浅色（推荐，企业 OA 主场景）/ 深色复刻展会风 / 双主题可选（工作量 +1 轮）
