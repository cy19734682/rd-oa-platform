## 1. 系统概述

**研发 OA 平台**是前卫表业工程技术研究中心自主建设的内部办公自动化综合平台，旨在解决研发过程中知识分散、标准难以检索、绩效考核流程不透明、过程资产无沉淀等痛点。平台采用 **主系统门户 + 子系统** 式信息架构——主系统门户（统一入口）→ 子系统 → 页面三级导航，提供**统一入口、统一账号、统一权限**的一站式办公体验，覆盖研发团队日常工作的核心场景。

### 核心特点

| 特点 | 说明 |
|------|------|
| 纯前端原型 | 无后端依赖，直接用浏览器打开即可运行 |
| 权限驱动 | 菜单、按钮、数据全部按角色权限动态展示 |
| 三级审核 | 经验案例入库、绩效考核等均走标准化审批流 |
| 水印防护 | 在线预览 PDF 自动叠加「用户名+时间」动态水印 |
| 待办聚合 | 右上角铃铛统一收集跨模块待办事项，实时提醒；主系统首页主区左下为「📌 我的待办」面板（v7.2 新增、v7.3 移到左侧并补创建日期、v7.4 与公告等高并去掉条数，逐条可点直达），侧栏摘要行已于 v7.5 下线（与主区面板重复） |
| 全局搜索 | 主系统顶部搜索框跨「研发公共 + 过程资产」检索，独立结果页 + 详情弹窗；子系统窗口仅研发公共 / 过程资产有搜索框且只搜本子系统（v5.5） |
| 通知公告 | 主系统门户**主区右下公告列表**（v7.2 起与待办各占一半宽、v7.3 移到右侧并把行高收到 40px、v7.4 与待办等高且页头去掉条数；逐条列出，每行含未读红点 + 类型标签 + 标题 + 日期，整行点击看详情）+ 系统管理内公告维护 |
| 常用应用 | 主系统门户固定常用应用磁贴，按账号持久化；另有「最近访问」自动记录（v5.2） |
| 外链聚合 | 第三方业务系统作为外链菜单项挂在所属子系统下（项目管理系统 / 项目看板 → 项目管理；自动化测试平台 → 研发公共），点击新窗口打开（v6.9） |

### 技术架构

```
前端技术栈：原生 JavaScript + HTML5 + CSS3
第三方依赖：SheetJS 0.18.5（Excel 解析），已内置 js/vendor/xlsx.full.min.js，不走 CDN（v6.7）
数据存储：  localStorage（会话级）+ localStorage（持久级）
路由方案：  自定义门户路由（主系统门户 → 子系统首页 → 子系统页），按窗口隔离持久化（主系统 `oa_route` / 子系统 `oa_route::<key>`）
```

## 2. 运行环境与启动方式

### 运行环境

| 项目 | 要求 |
|------|------|
| 浏览器 | Chrome 90+、Edge 90+、Firefox 90+、Safari 14+ |
| 操作系统 | Windows 10/11、macOS、Linux |
| Node.js（可选） | 用于启动本地静态服务器 |
| 网络 | **无需联网**：唯一的第三方库（SheetJS）已内置到 `js/vendor/`，断网 / 内网环境可完整运行（v6.7 起不再依赖 CDN） |

### 启动方式

**方式一：直接打开（推荐原型演示）**
```
直接双击 index.html 文件，用浏览器打开即可
```

**方式二：本地静态服务器（推荐开发调试）**
```bash
# 使用 npx 启动（需 Node.js 环境）
cd rd-oa-platform
npx serve -p 3000

# 或使用 pnpm
pnpm dlx serve -p 3000
```
启动后访问 `http://localhost:3000` 即可。

 ⚠️ **注意**：子系统已改为**独立窗口打开**（`subs/<key>.html`），其登录态依赖与主系统同源的 sessionStorage / localStorage 共享。通过 `file://` 协议打开时，浏览器将每个文件视为独立 origin，存储互不共享——子系统窗口会反复要求登录，且外链跳转可能被拦截。**请使用本地服务器方式访问**（方式二）。

## 3. 登录与认证

### 3.1 登录页面

打开系统后首先进入登录页面，左侧展示公司名称"前卫表业"，右侧为登录表单。

### 3.2 演示账号

系统预置了多组演示账号，点击登录页面底部的标签即可**自动填充账号密码**：

| 工号/账号 | 角色 | 默认密码 | 说明 |
|-----------|------|----------|------|
| **8001** | 一般人员 | `123456` | 普通研发人员，拥有查看和导出权限 |
| **8004** | 项目经理 | `123456` | 可对过程资产进行新增/编辑/删除 |
| **8005** | 主管 | `123456` | 可对下属进行绩效考核打分 |
| **8006** | 部门领导 | `123456` | 最终审核考核表、配置互评人 |
| **admin** | 系统管理员 | `admin123` | 超级管理员，拥有全部权限 |

### 3.3 登录操作步骤

1. 在「用户名 Account」输入框中输入工号或账号
2. 在「密码 Password」输入框中输入对应密码
3. 点击「登 录」按钮
4. 登录成功后进入主系统门户，按权限点选子系统进入

### 3.4 会话保持

- 登录成功后，会话信息持久化到 **sessionStorage**（`oa_session`）
- 刷新页面可自动恢复登录状态和上次浏览位置
- **关闭浏览器标签页** → 会话丢失，需重新登录
- **点击头像下拉 → 切换角色/退出登录** → 清除会话并返回登录页

### 3.5 登录拦截机制

未登录时直接访问系统内部路由会被拦截器拦截，强制跳转回登录页面，有效保护子系统入口安全。

## 4. 整体界面导览

平台为 **一主四子、窗口级分离** 架构：登录后进入**主系统门户**（各子系统的统一入口，含系统管理），点击业务子系统卡即**新窗口打开该子系统的独立页面**（`subs/<key>.html`，独立 URL、独立样式）。门户只放子系统卡——外部系统不再是门户级卡片，而是挂在各子系统菜单里的外链菜单项（v6.9），点开后同样新窗口打开第三方系统。各窗口底层仍同项目、同登录态、同数据层。

```
┌─────────────────────────────────────────────────────────────────────┐
│ 主系统窗口 index.html                                                │
│ 顶部导航栏：Logo（回门户） / 🔍 全局搜索 / 时钟 / 🔔 铃铛 / 👤 头像     │
│ 面包屑行：工作台（常规面包屑；v7.0 起公告已移出，v7.8 改称）           │
│ 内容区：┌─ 左侧栏（280px 全高常驻）─┐ ┌─ 右侧主区 ────────────┐       │
│         │ 用户卡+问候语+日期+进度 │ │ 业务子系统（4 个）       │      │
│         │ 🧭 常用应用（紧凑磁贴)  │ │ 📁 项目管理  🔬 研发公共 │      │
│         │ 🕘 最近访问（自动记录） │ │ 📐 过程资产  📈 绩效管理 │      │
│         │ ⚙️ 系统管理（仅管理员） │ │ 待办 50%  │  公告 50%    │      │
│         │                         │ │ 📌 待办  │  📢 公告      │      │
│         └─────────────────────────┘ └────────────────────────┘        │
│         （主区 v7.6：入口块与双栏按 20px 间距自然排列，与左侧栏等高） │
└─────────────────────────────────────────────────────────────────────┘
        │ 点击子系统卡 / 常用应用 / 待办与搜索的「进入」
        ▼ window.open 新窗口
┌─────────────────────────────────────────────────────────────────────┐
│ 子系统窗口 subs/<key>.html（proj / dev / asset / perf 各一页）        │
│ 顶部导航栏：主系统同款 Logo + 子系统名称（点击回门户）/ 搜索 / 时钟等  │
│   （🔍 搜索仅研发公共、过程资产保留，且只搜本子系统内容）              │
│ 内容区：该子系统自己的二级菜单磁贴 → 页面（面包屑一级为本子系统名）    │
│ 视觉：独立 CSS（css/subs/<key>.css）覆写主题色与组件，窗口间可感知差异  │
└─────────────────────────────────────────────────────────────────────┘
```

### 门户导航流程

```

   ├── 点击子系统卡 → window.open subs/<key>.html（新窗口，独立样式）
   │     └── 子系统首页（工作台：定位条 + 数据摘要 + 功能入口卡）→ 点击入口卡 → 子系统页（同时记入侧栏「最近访问」）
   │           └── 含三级子项的菜单 → 三级子项分组磁贴页 → 点击磁贴 → 三级子系统页
   ├── 子系统内的外链菜单项（项目管理 → 项目管理系统 / 项目看板；研发公共 → 自动化测试平台）→ 新窗口打开第三方系统
   ├── 点击侧栏常用应用或最近访问（内部项）→ 新窗口打开子系统并直达固定页面（?m=二级页）
   ├── 铃铛待办 / 搜索「进入」→ 新窗口打开目标子系统并落到对应页面
   ├── 侧栏「⚙️ 系统管理」（仅系统管理员）→ 主系统窗口内直达系统管理板块
   ├── 主区右下公告列表 → 点击任意一行看公告详情（自动标记已读，该行红点消失；v7.1 起由单条公告条改为列表，v7.3 移到右侧）
   └── 主区左下「我的待办」→ 点击任一条直达办理位置（与铃铛同源，跨子系统自动新窗口落地；v7.3 每条右侧带创建日期）；页头「全部 ›」打开铃铛面板（v7.4 去掉「共 N 条」计数）
```

- **子系统窗口启动门控**：未登录显示「请先登录」引导（回主系统登录）；角色无该子系统权限显示「无权访问」提示；
- **深链落地**：`subs/dev.html?m=stdHome` 直接落到标准库页；主系统 `index.html?m=sys&v=sysAcct` 直接落到账号管理；
- **路由持久化按窗口隔离**：主系统 `oa_route`，各子系统窗口 `oa_route::<key>`，互不污染；
- 业务子系统卡为竖排卡片（48px 主题渐变图标 + 名称 16px / 编码小字 + 右上角状态角标 + 描述 + 「进入系统 →」底栏，**一行 4 个**、单卡 265×195，v7.2 定 4 列 / v7.3 加高 / v7.6 收到 195px），v6.9 起不再带「内部系统 / 外部系统」胶囊（门户只有子系统卡，标签已无对比意义），v7.1 起底栏不再显示「N 个功能入口」；主区下方为待办 / 公告双栏（v7.4 起两者等高），hero 大标题已下线（v7.0）；
- 四个子系统的独立样式（`css/subs/<key>.css`）分别覆写主题变量（proj 蓝 / dev 绿 / asset 青 / perf 紫）与局部组件，在共享整站样式之后加载。


## 5. 角色与权限体系

### 5.1 角色定义

系统内置 **5 个角色**，每个角色拥有不同的菜单和操作权限：

| 角色 | 角色编码 | 默认账号 | 权限范围摘要 |
|------|----------|----------|--------------|
| **一般人员** | `staff` | 8001 | 所有模块的**查看**和**导出**权限，标准管理员功能除外 |
| **项目经理** | `projManager` | 8004 | 在一般人员基础上，额外拥有**过程资产**模块 4 个子菜单的新增/编辑/删除权限 |
| **主管** | `supervisor` | 8005 | 在一般人员基础上，额外拥有**绩效管理**模块的模板管理、月度/年度考核编辑权限 |
| **部门领导** | `deptLeader` | 8006 | 在主管基础上，额外拥有**年终考核汇总**编辑权限、**互评管理**配置权限 |
| **系统管理员** | `sysAdmin` | admin | **超级管理员**，拥有全部模块全部权限，负责账号/角色/菜单/字典/日志管理 |

### 5.2 权限控制维度

系统采用**两级权限控制**模型：

```
┌─────────────────────────────────────┐
│  第一层：模块级权限（菜单可见性）      │
│  角色 → 模块 → 子菜单 → 三级子菜单    │
├─────────────────────────────────────┤
│  第二层：业务级操作权限（按钮可见性）  │
│  每个菜单项可声明 6 种 Action 权限：   │
│  view（查看） add（新增） edit（编辑） │
│  delete（删除） export（导出）admin（管理员）│
└─────────────────────────────────────┘
```

### 5.3 权限配置方法

仅 **系统管理员** 可配置角色权限：

1. 登录 admin 账号
2. 进入「系统管理 → 角色管理」
3. 找到目标角色，点击「权限配置」按钮
4. 在弹窗中勾选各模块/子菜单的访问权限，以及具体的操作权限（查看/新增/编辑/删除/导出/管理员）
5. 点击「💾 保存配置」生效

权限变更后，所有打开该系统的页面会自动刷新菜单，无需手动刷新浏览器。

### 5.4 内置角色与自定义角色

- **内置角色**（staff、projManager、supervisor、deptLeader、sysAdmin）：不可删除，名称/描述跟随代码更新，权限可调整
- **自定义角色**：由系统管理员在角色管理中新增，默认继承一般人员权限，可按需扩展

**v7.6 布局规则**：`.portal-home` 保持 `align-items: stretch`（v7.5 起），左侧栏有固定高度（`100vh - 146px`），主区因此仍与侧栏**同高**（1440×1000 实测两边都是 854px）。但 `.portal-main-col` 的 `justify-content: space-between` 已去掉，改为纯 `flex-direction: column; gap: 20px`——上半「标题 + 卡片网格」（`.portal-main-block`）紧接双栏，双栏之后剩余的高度就留在主区底部。`.sub-grid` 与 `.portal-split` 的 `margin-bottom` 仍为 0（间距统一由主区 `gap` 控制）；内容比容器高时 `flex-shrink: 0` 保证卡片与列表不被压缩，整块撑高、页面正常滚动；≤1200px 侧栏置顶为横排时主区高度回归内容高度（无需额外判断）。

两栏各占一半宽（`grid-template-columns: 1fr 1fr`，≤900px 单列堆叠）。**v7.3 起左右互换**：左边「**要做什么**」（待办，可操作）在前，右边「**要知道什么**」（公告，只读）在后。**v7.4 起两块面板等高**（`align-items: stretch`，grid 默认）：两栏共用同一行高，于是「待办 + 公告」作为一个整体成为**上下左右都齐平的矩形**，与上方业务子系统网格**左右两端同宽**（1440 实测：网格与双栏均 `x=316 / 宽 1106`，两块面板各 543×297）。

这里要区分「**容器等高**」与「**条目拉伸**」：面板被拉高后，多出来的高度由列表容器吃掉（`.pnt-list / .pdt-list` 的 `flex: 1 1 auto`），条目本身行高不变（公告固定 40px、待办自适应约 49px）——所以 v7.2 那种「公告条目被摊松」的问题不会复发；代价是条目少的一侧底部会留一段白（5 条待办 297px vs 4 条公告 297px，公告列表实际占用约 212px，底部留白 85px 左右），这是「等高 + 紧凑行高」的必然取舍。只有一侧有内容时（例如全新环境无公告），`:only-child` 让该面板独占整行。

#### 6.5.2 📅 月度绩效考核

##### 考核流程

月度考核采用**项目经理 → 直接主管 → 部门领导**三级打分机制：

```
┌──────────────────────────────────────────────────────────┐
│  ① 项目经理打分                                          │
│  - 逐项填写任务项内容、PM 打分（0-100）、PM 评价          │
│  - 提交后锁定本表，进入下一环节                            │
├──────────────────────────────────────────────────────────┤
│  ② 直接主管打分                                          │
│  - 逐项填写主管打分（0-100）、主管评价                    │
│  - 系统自动取 PM 打分和主管打分的**最大值**填入领导打分栏  │
│  - 可对高分进行预填，也可手动调整                          │
├──────────────────────────────────────────────────────────┤
│  ③ 部门领导归档                                          │
│  - 最终审核确认                                           │
│  - 可打回（仅领导有此权限），退回指定考核人重改            │
└──────────────────────────────────────────────────────────┘
```

##### 表单字段说明

| 列名 | 说明 |
|------|------|
| 大类 / 小类 | 模板中定义的考核分类层级 |
| 考核标准 | 具体的考核项名称 |
| 权重 | 该项在总分中的占比 |
| 任务项 | 被考核人当月的具体工作任务描述 |
| PM 打分 | 项目经理给出的分数（0-100） |
| 主管打分 | 直接主管给出的分数（0-100） |
| 领导打分 | 部门领导最终确认的分数（预填为 PM/主管最大值） |
| PM / 主管 / 领导评价 | 各角色的评语（多行文本） |

##### 评分联动逻辑

系统自动同步 PM 打分和主管打分到领导打分预填值：
- 当 PM 打分和主管打分都填写后，**领导打分自动取两者的最大值**
- 支持手动覆盖预填值

##### 状态流转

| 状态 | 说明 | 可操作 |
|------|------|--------|
| 考核表已创建 | 表已生成但未开始打分 | 无 |
| 待 PM 打分 | PM 尚未填写 | PM 可打分 |
| PM 已打分，待主管打分 | PM 已提交 | 主管可打分 |
| 主管已打分，待领导归档 | 主管已提交 | 领导可归档/打回 |
| 已打回 | 领导打回 | 相关考核人可重新编辑 |
| 已完成 | 领导已归档 | 任何人不可修改 |

**持久化语义**（`oa_menus` 为唯一事实源）：
- 菜单管理中的新增 / 删除 / 改名 / 排序均写入 localStorage，**刷新后保留**，不会被种子数据恢复
- 种子同步按「指纹闸门」执行：`DEFAULT_MODULES` 的内容哈希存于 `oa_menu_seed_hash`，仅当代码里的种子相对上次加载发生过变更（发版）时才同步一次——注入种子新增的菜单、清理种子移除的菜单，完成后刷新指纹；种子未变更时完全尊重用户的运行时数据
- **删除墓碑**（`oa_menu_deleted_keys`）：用户删掉的种子菜单 key 会记入墓碑，后续发版同步不会把它重新灌回来
- 用户自建的菜单带 `custom` 标记，种子清理时不删除；用户改过的种子菜单带 `edited` 标记，种子元数据（名称/图标/排序/actions）不覆盖
- 删除菜单会同步清理所有角色的对应 perms

## 8. 常见问题解答

### Q1：刷新页面后为什么账号还在？

系统在登录成功后会将会话信息（`oa_session`）写入 sessionStorage，每次打开页面时优先从 sessionStorage 恢复登录状态。刷新页面不会清除 sessionStorage，所以账号保持登录。

### Q2：我登录后看不到标准库/绩效管理等菜单？

菜单按角色权限动态显示。请确认你的账号角色（可点击右上角头像查看）：
- 一般人员：可查看所有模块但无新增/编辑/管理员权限
- 如需权限变更，请联系系统管理员在「系统管理 → 角色管理 → 权限配置」中为你的角色授权

### Q3：为什么有些按钮（如"新建标准"）点不动？

这些按钮受**业务级 Action 权限**控制。每个菜单项声明了具体的操作权限（view/add/edit/delete/export/admin），只有你的角色拥有对应权限时按钮才会显示或可操作。系统管理员可在权限配置弹窗中调整。

### Q4：绩效考核表提交后还能修改吗？

**不能自行修改**。一旦 PM 或主管提交打分，本表会自动锁定并流转到下一环节。如需修改，需由上级角色执行**打回**操作（仅部门领导和系统管理员有打回权限），被打回的考核表会退回到上一环节重新编辑。

### Q5：经验案例库查重是怎么实现的？

目前原型阶段的查重机制是基于**标题指纹 + 附件哈希**的前端比对：
- 标题指纹：对标题文本进行归一化处理后计算相似度
- 附件哈希：对上传文件内容计算哈希值判断是否完全重复
- 发现疑似相似时会弹出相似度提示，用户确认非重复后仍可继续提交

### Q6：PDF 在线预览的水印能去掉吗？

**不能**，水印是前端在渲染时通过 CSS 叠加的，基于「当前登录用户名 + 时间戳」动态生成，旨在防止截屏泄密。这是安全设计，确保每个查看/下载行为都可追溯。

### Q7：如何添加新的角色或修改默认权限？

步骤：
1. 登录 admin 系统管理员账号
2. 进入「系统管理 → 角色管理」
3. 点击「+ 新增角色」（自定义角色）或选中已有角色点击「权限配置」
4. 在弹窗中勾选模块/子菜单/三级菜单的访问权限
5. 同时勾选叶子节点的业务级操作权限（查看/新增/编辑等）
6. 保存后自动对所有打开系统的页面生效

### Q8：外部系统（项目管理等）的地址在哪里配置？如何新增一个外部系统？

**修改地址**：在「系统管理 → 菜单管理 → **子系统菜单**」tab 中，展开对应子系统（如「项目管理」），找到那条外链菜单项（如「项目管理系统」，类型列显示 `external`），点击编辑修改其 **URL**（保存后全用户生效）。v6.9 前的「门户配置 → 编辑 → 跳转链接」入口已删除。

**新增外部系统**：在同一个「子系统菜单」tab 中，选中要挂载的子系统 → 「+ 新增子菜单」，类型选 `external`，填写名称 / 图标 / URL（须以 `http://` 或 `https://` 开头）/ 排序即可。保存后该外链会同时出现在**该子系统首页的入口卡**（虚线描边 + 「外部链接」胶囊 + 「前往 ↗」）和**该子系统的左侧菜单**里，点击新窗口打开；也可在侧栏「🧭 常用应用 → 管理」中把它固定成磁贴。

门户子系统卡由源代码 `js/modules/config-portal.js` 的 `DEFAULT_PORTAL_APPS` 种子定义（只有 `proj` / `dev` / `asset` / `perf`，发版后自动同步，见 6.6.4）；外链菜单项的种子在 `js/modules/config-menu.js` 的 `DEFAULT_MODULES` 中，种子指纹变化后会自动注入到用户已有数据里。

### Q9：如何重置所有数据？

方法一（推荐）：清除浏览器 localStorage 和 localStorage

```javascript
// F12 打开浏览器控制台，输入以下命令
localStorage.clear();
sessionStorage.clear();
location.reload();
```

方法二：清除浏览器缓存后重新打开页面，所有数据会重置为代码中的种子 Mock 数据。

### Q10：待办提醒弹窗能关闭吗？

可以。点击弹窗右下角的「知道了」按钮后，本次登录期间不再自动弹出。如需再次查看，点击右上角 🔔 铃铛图标即可。

### Q11：子系统为什么在新窗口打开？能改回同窗口切换吗？

这是 v2「窗口级分离」的刻意设计：每个子系统是独立页面（`subs/<key>.html`）+ 独立样式（`css/subs/<key>.css`），形式上是一个独立站点，未来可单独打包部署；底层仍共享同一套代码、登录态与数据。若需要改回同窗口，把 `js/modules/views.js` 中 `_subAppCardHtml` 的 `openSubsystem('${mod}')` 与 `views-portal.js` 中 `openFavApp` 的 `__jumpSub(mod, sub)` 换为站内导航函数即可（壳函数已移除，需恢复 router 的 `enterSubsystem` 语义）。

### Q12：子系统窗口的样式在哪里改？

每个子系统一个独立样式文件：`css/subs/proj.css`（蓝）/ `dev.css`（绿）/ `asset.css`（青）/ `perf.css`（紫）。它们在整站 `css/style.css` **之后**加载，通过覆写 CSS 变量（`--primary` / `--headerBg` / `--iconBlue` / `--bg` / `--radius` 等）与少量局部组件实现主题差异；改样式只动对应子系统的文件，不影响其他窗口。

### Q13：Excel 导入 / 下载模板用的解析库放在哪？还能改回 CDN 吗？

本地文件 `js/vendor/xlsx.full.min.js`（SheetJS 0.18.5，约 860 KB）。v6.7 之前由 `cdn.jsdelivr.net` **同步**加载，实测单个请求就要 3 秒以上（首屏 domInteractive ≈ 5.2s），断网时更是整页空白无提示，故改为本地引用并加 `defer`：既不阻塞 HTML 解析，也仍在 `DOMContentLoaded` 前就绪。

引用点共 4 处：`index.html`（`js/vendor/...`）与 `subs/dev.html`、`subs/asset.html`、`subs/perf.html`（`../js/vendor/...`）；`subs/proj.html` 无数据层，不需要。升级版本直接替换该文件即可，**不要改回 CDN**。库缺失时页面不会白屏，只在点击「下载模板 / 选择 Excel」时提示「Excel 组件未就绪，请刷新页面后重试」（`js/modules/views-pa-task.js`）。

### Q14：表格列宽为什么不是均分？怎么调？

v6.8 之前所有表格是 `table-layout:fixed` 且无列宽定义 → 各列**均等分**，长文本列（描述 / 标题 / 模板名称）被硬裁、短列（编码 / 状态）白占宽度。现在 `js/modules/helpers.js` 里维护 `TABLE_COL_RATIOS`：

- key = 表头数组 `join("|")`，value = 与表头等长的百分比数组（合计 100）；
- `table()` 命中配置时生成 `<colgroup>` 并给表格加 `class="tbl-ratio"`，在 fixed 布局下按比例**精确**分配（实测百分比列不会被 `--last-col-width` 抢占，末列也随之按比例走）；
- 未命中的表保持原均分行为，可以按需逐步补；
- 手工拼接的三张表（部门管理 / 数据字典 / 通知公告）显式调用 `colgroup(TH.sysDept)` 之类的签名生成器。

改的时候注意：

1. **改表头文案等于改 key**，比例配置会失配。`colgroup()` 会校验长度并在不符时自动回退均分，不会错位，但记得同步改 `TABLE_COL_RATIOS`；
2. 长文本单元格用 `.cell-ell`（单行省略，配合 `title` 悬停看全文），标签组用 `.cell-wrap`（允许折行）。此前单元格内是 `inline-block` 子元素时，`td` 的 `text-overflow` 不生效，表现为「文字被硬切且没有省略号」；
3. 操作列按钮在 ≤1200px 会自动收紧左右留白与按钮间距（`@media` 内），避免 4 个按钮折成两行把行高撑高。
