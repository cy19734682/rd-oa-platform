## 1. 系统概述

**研发 OA 平台**是前卫表业工程技术研究中心自主建设的内部办公自动化综合平台，旨在解决研发过程中知识分散、标准难以检索、绩效考核流程不透明、过程资产无沉淀等痛点。平台采用 **主系统门户 + 子系统** 式信息架构——主系统门户（统一入口）→ 子系统 → 页面三级导航，提供**统一入口、统一账号、统一权限**的一站式办公体验，覆盖研发团队日常工作的核心场景。

### 核心特点

| 特点 | 说明 |
|------|------|
| 纯前端原型 | 无后端依赖，直接用浏览器打开即可运行 |
| 权限驱动 | 菜单、按钮、数据全部按角色权限动态展示 |
| 三级审核 | 经验案例入库、绩效考核等均走标准化审批流 |
| 水印防护 | 在线预览 PDF 自动叠加「用户名+时间」动态水印 |
| 待办聚合 | 右上角铃铛统一收集跨模块待办事项，实时提醒；首页左侧栏另有待办摘要行（v5.2，点击弹同款面板） |
| 全局搜索 | 主系统顶部搜索框跨「研发公共 + 过程资产」检索，独立结果页 + 详情弹窗；子系统窗口仅研发公共 / 过程资产有搜索框且只搜本子系统（v5.5） |
| 通知公告 | 主系统门户 crumb 公告条展示最新一条（未读提醒，点击看详情；v5.9 去掉「查看更多」）+ 系统管理内公告维护 |
| 常用应用 | 主系统门户固定常用应用磁贴，按账号持久化；另有「最近访问」自动记录（v5.2） |
| 外链聚合 | 第三方业务系统通过外部子系统磁贴统一入口 |

### 技术架构

```
前端技术栈：原生 JavaScript + HTML5 + CSS3 + SheetJS (xlsx 解析)
数据存储：  localStorage（会话级）+ localStorage（持久级）
路由方案：  自定义门户路由（主系统门户 → 子系统首页 → 子系统页），按窗口隔离持久化（主系统 `oa_route` / 子系统 `oa_route::<key>`）
```

## 2. 运行环境与启动方式

### 运行环境

| 项目 | 要求 |
|------|------|
| 浏览器 | Chrome 90+、Edge 90+、Firefox 90+、Safari 14+ |
| 操作系统 | Windows 10/11、macOS、Linux |
| Node.js（可选） | 用于启动本地静态服务器 |

### 启动方式

**方式一：直接打开（推荐原型演示）**
```
直接双击 index.html 文件，用浏览器打开即可
```

**方式二：本地静态服务器（推荐开发调试）**
```bash
# 使用 npx 启动（需 Node.js 环境）
cd rd-oa-platform
npx serve -p 3000

# 或使用 pnpm
pnpm dlx serve -p 3000
```
启动后访问 `http://localhost:3000` 即可。

 ⚠️ **注意**：子系统已改为**独立窗口打开**（`subs/<key>.html`），其登录态依赖与主系统同源的 sessionStorage / localStorage 共享。通过 `file://` 协议打开时，浏览器将每个文件视为独立 origin，存储互不共享——子系统窗口会反复要求登录，且外链跳转可能被拦截。**请使用本地服务器方式访问**（方式二）。

## 3. 登录与认证

### 3.1 登录页面

打开系统后首先进入登录页面，左侧展示公司名称"前卫表业"，右侧为登录表单。

### 3.2 演示账号

系统预置了多组演示账号，点击登录页面底部的标签即可**自动填充账号密码**：

| 工号/账号 | 角色 | 默认密码 | 说明 |
|-----------|------|----------|------|
| **8001** | 一般人员 | `123456` | 普通研发人员，拥有查看和导出权限 |
| **8004** | 项目经理 | `123456` | 可对过程资产进行新增/编辑/删除 |
| **8005** | 主管 | `123456` | 可对下属进行绩效考核打分 |
| **8006** | 部门领导 | `123456` | 最终审核考核表、配置互评人 |
| **admin** | 系统管理员 | `admin123` | 超级管理员，拥有全部权限 |

### 3.3 登录操作步骤

1. 在「用户名 Account」输入框中输入工号或账号
2. 在「密码 Password」输入框中输入对应密码
3. 点击「登 录」按钮
4. 登录成功后进入主系统门户，按权限点选子系统进入

### 3.4 会话保持

- 登录成功后，会话信息持久化到 **sessionStorage**（`oa_session`）
- 刷新页面可自动恢复登录状态和上次浏览位置
- **关闭浏览器标签页** → 会话丢失，需重新登录
- **点击头像下拉 → 切换角色/退出登录** → 清除会话并返回登录页

### 3.5 登录拦截机制

未登录时直接访问系统内部路由会被拦截器拦截，强制跳转回登录页面，有效保护子系统入口安全。

## 4. 整体界面导览

平台为 **一主四子、窗口级分离** 架构：登录后进入**主系统门户**（各子系统的统一入口，含系统管理），点击业务子系统卡即**新窗口打开该子系统的独立页面**（`subs/<key>.html`，独立 URL、独立样式）；外部系统同样新窗口打开。各窗口底层仍同项目、同登录态、同数据层。

```
┌─────────────────────────────────────────────────────────────────────┐
│ 主系统窗口 index.html                                                │
│ 顶部导航栏：Logo（回门户） / 🔍 全局搜索 / 时钟 / 🔔 铃铛 / 👤 头像     │
│ 面包屑行：📢 公告条（最新一条通知，无边框无背景，点击看详情）          │
│ 内容区：┌─ 左侧栏（280px 全高常驻）─┐ ┌─ 右侧主区 ────────────┐      │
│         │ 用户卡+问候语+日期+进度  │ │ hero 主标题（无操作钮）  │      │
│         │ ⏳ 我的待办（N 条摘要）  │ │ → 业务子系统卡网格       │      │
│         │ 🧭 常用应用（紧凑磁贴)   │ │ → 外部系统卡网格         │      │
│         │ 🕘 最近访问（自动记录）  │ │                        │      │
│         │ ⚙️ 系统管理（仅管理员）  │ │                        │      │
│         └─────────────────────────┘ └────────────────────────┘      │
│         （系统管理经侧栏链接进入；待办在摘要行与右上角铃铛）           │
└─────────────────────────────────────────────────────────────────────┘
        │ 点击内部子系统卡 / 常用应用 / 待办与搜索的「进入」
        ▼ window.open 新窗口
┌─────────────────────────────────────────────────────────────────────┐
│ 子系统窗口 subs/<key>.html（proj / dev / asset / perf 各一页）        │
│ 顶部导航栏：主系统同款 Logo + 子系统名称（点击回门户）/ 搜索 / 时钟等  │
│   （🔍 搜索仅研发公共、过程资产保留，且只搜本子系统内容）              │
│ 内容区：该子系统自己的二级菜单磁贴 → 页面（面包屑一级为本子系统名）    │
│ 视觉：独立 CSS（css/subs/<key>.css）覆写主题色与组件，窗口间可感知差异  │
└─────────────────────────────────────────────────────────────────────┘
```

### 界面各区域说明

| 区域 | 功能说明 |
|------|----------|
| **顶部 Logo** | 主系统窗口显示平台标识，点击回主系统门户；子系统窗口（v5.5 起）与主系统同构——同一 SVG Logo + 子系统名称（名称取自门户配置），点击回主门户（opener 存活则聚焦原门户标签，否则新开） |
| **🔍 搜索框** | 顶部居中，回车触发；结果在独立搜索页展示，点击条目弹窗查看详情，弹窗内「进入」**新窗口打开对应子系统并落页**。v5.5 起按窗口限定范围：主系统窗口为全局搜索（研发公共：标准库 / 经验案例库 + 过程资产：开发规范 / 文档模板 / 设计规范 / 评审 Checklist，按角色权限过滤）；子系统窗口中仅**研发公共 / 过程资产**保留搜索框，且只搜本子系统内容（项目管理 / 绩效管理无搜索功能） |

| **🔔 铃铛** | 显示待办事项数量角标，点击查看全部待办；跨模块待办点击后**新窗口打开目标子系统**并落到对应页面（目标就是当前窗口时直接弹出处理模态） |
| **👤 头像** | 显示当前登录角色，点击弹出下拉菜单；子系统窗口内「退出登录」后显示门控引导回主系统登录 |
| **面包屑** | 主系统首页只显示 crumb 公告条（最新一条通知公告，未读红点 + 点击标题看详情，无「主系统」一级；v5.9 去掉「查看更多」，左右内边距 290px，由 `.crumb.is-home` 标记；v6.6 起搜索结果页同样**不带** `is-home`，按普通页面 20px 缩进）；其余页面一级为「主系统」可点击回门户（保持常规 20px 内边距）；**子系统窗口（v5.5 起）一级为本子系统名**（点击回本子系统首页），不再出现「主系统」，回主门户统一点击顶栏 Logo |
| **返回条** | v5.5 起子系统二级页不再显示返回条（回门户点顶栏 Logo，回上级走面包屑）；仅三级子项页显示「← 返回父级分组」回到分组磁贴页 |
| **主内容区** | 主系统窗口展示门户（左侧栏 + 右侧主区）与系统管理；子系统窗口只展示该子系统自己的菜单树与页面；**子系统首页为工作台式布局（v6.5）**：定位条（子系统名 + 一句话定位）→ 数据摘要四格（无数据层的项目管理省略，数值不带单位）→「功能入口」6 列卡栅格（图标 + 名称 + 描述 + 细线底栏）；主系统内的模块页（系统管理）仍为原磁贴铺开形态 |
| **首页左侧栏** | 仅主系统门户：宽 280px、高度撑满可用区域（sticky 常驻，过高时栏内自滚动），浅色独立底色与主区分化；自上而下为用户卡 + 问候区（含日期进度）、⏳ 我的待办摘要行、🧭 常用应用、🕘 最近访问、⚙️ 系统管理（仅系统管理员）；窄屏（≤1200px）降级为置顶两列网格，此时主区改为通栏（v6.1 修正原先主区会收成内容宽的问题） |

### 门户导航流程

```
主系统门户（左侧栏：用户卡/待办摘要/常用应用/最近访问/系统管理〔仅管理员〕；右侧主区：hero + 业务子系统卡 + 外部系统卡，均按角色过滤）
   ├── 点击内部子系统卡 → window.open subs/<key>.html（新窗口，独立样式）
   │     └── 子系统首页（工作台：定位条 + 数据摘要 + 功能入口卡）→ 点击入口卡 → 子系统页（同时记入侧栏「最近访问」）
   │           └── 含三级子项的菜单 → 三级子项分组磁贴页 → 点击磁贴 → 三级子系统页
   ├── 点击外部系统卡 → 新窗口打开第三方系统（项目管理 / 项目看板 / 自动化测试平台）
   ├── 点击侧栏常用应用或最近访问（内部项）→ 新窗口打开子系统并直达固定页面（?m=二级页）
   ├── 铃铛待办 / 侧栏待办摘要行 / 搜索「进入」→ 新窗口打开目标子系统并落到对应页面
   ├── 侧栏「⚙️ 系统管理」（仅系统管理员）→ 主系统窗口内直达系统管理板块
   └── 面包屑行 crumb 公告条 → 点击标题看详情（v5.9 起无「查看更多」入口）
```

- **子系统窗口启动门控**：未登录显示「请先登录」引导（回主系统登录）；角色无该子系统权限显示「无权访问」提示；
- **深链落地**：`subs/dev.html?m=stdHome` 直接落到标准库页；主系统 `index.html?m=sys&v=sysAcct` 直接落到账号管理；
- **路由持久化按窗口隔离**：主系统 `oa_route`，各子系统窗口 `oa_route::<key>`，互不污染；
- 业务子系统卡为竖排卡片（渐变图标底座 + 名称 + 类型胶囊 + 描述 + 三格字段 + 操作链），外链卡以虚线边框 + 灰色图标底座区分；
- 四个子系统的独立样式（`css/subs/<key>.css`）分别覆写主题变量（proj 蓝 / dev 绿 / asset 青 / perf 紫）与局部组件，在共享整站样式之后加载。


## 5. 角色与权限体系

### 5.1 角色定义

系统内置 **5 个角色**，每个角色拥有不同的菜单和操作权限：

| 角色 | 角色编码 | 默认账号 | 权限范围摘要 |
|------|----------|----------|--------------|
| **一般人员** | `staff` | 8001 | 所有模块的**查看**和**导出**权限，标准管理员功能除外 |
| **项目经理** | `projManager` | 8004 | 在一般人员基础上，额外拥有**过程资产**模块 4 个子菜单的新增/编辑/删除权限 |
| **主管** | `supervisor` | 8005 | 在一般人员基础上，额外拥有**绩效管理**模块的模板管理、月度/年度考核编辑权限 |
| **部门领导** | `deptLeader` | 8006 | 在主管基础上，额外拥有**年终考核汇总**编辑权限、**互评管理**配置权限 |
| **系统管理员** | `sysAdmin` | admin | **超级管理员**，拥有全部模块全部权限，负责账号/角色/菜单/字典/日志管理 |

### 5.2 权限控制维度

系统采用**两级权限控制**模型：

```
┌─────────────────────────────────────┐
│  第一层：模块级权限（菜单可见性）      │
│  角色 → 模块 → 子菜单 → 三级子菜单    │
├─────────────────────────────────────┤
│  第二层：业务级操作权限（按钮可见性）  │
│  每个菜单项可声明 6 种 Action 权限：   │
│  view（查看） add（新增） edit（编辑） │
│  delete（删除） export（导出）admin（管理员）│
└─────────────────────────────────────┘
```

### 5.3 权限配置方法

仅 **系统管理员** 可配置角色权限：

1. 登录 admin 账号
2. 进入「系统管理 → 角色管理」
3. 找到目标角色，点击「权限配置」按钮
4. 在弹窗中勾选各模块/子菜单的访问权限，以及具体的操作权限（查看/新增/编辑/删除/导出/管理员）
5. 点击「💾 保存配置」生效

权限变更后，所有打开该系统的页面会自动刷新菜单，无需手动刷新浏览器。

### 5.4 内置角色与自定义角色

- **内置角色**（staff、projManager、supervisor、deptLeader、sysAdmin）：不可删除，名称/描述跟随代码更新，权限可调整
- **自定义角色**：由系统管理员在角色管理中新增，默认继承一般人员权限，可按需扩展

## 6. 功能模块详解

### 6.1 主系统门户（OA 门户首页）

点击顶部 Logo 或登录成功后进入主系统门户。页面为**「左侧栏 + 右侧主区」**布局（v3 起，v4/v5 精简）：左侧栏浅色独立底色、全高常驻，只放「与我相关」的随身信息与管理入口；右侧主区只留系统入口。

#### 6.1.1 首页左侧栏（随身信息 + 系统管理）

宽 280px、高度撑满可用区域（`100vh - 146px`，sticky 常驻，过高时栏内自滚动），浅蓝灰底色 + 圆角描边与主区（页面底 + 白卡）形成视觉区分。自上而下五块，除「最近访问」按账号记录一次访问历史外，其余数据全部与铃铛、弹窗同源，零新增存储：

| 块 | 内容 |
|----|------|

| ② 问题分析过程 | 排查路径 | "逐步缩小范围的分析过程" |
| ③ 问题根因 | 根本原因 | "定位到的最终根因" |
| ④ 解决方法 | 解决方案与验证 | "实施的修复措施及验证结果" |
| ⑤ 经验总结 | 可复用的经验 | "对类似问题的预防建议" |

附加信息：标题、产品型号、关键字标签、附件上传。

 ⚠️ **敏感脱敏提示**：提交前请对正文与附件中的客户信息、用户信息、数量信息等进行脱敏处理，主管初审会复核把关。

##### 自动查重

提交时系统自动按「标题指纹 + 附件哈希」进行查重，发现疑似相似案例会提示相似度百分比，用户确认非重复后可继续提交。

##### 三级审核流程

```
提交 → ① 直接主管初审 → ② 部门领导审核 → ③ 副总工审批 → 入库
         │                │                │
         └── 可退回重提   └── 可退回重提   └── 可退回重提
```

每个审核环节都可：
- ✅ **通过**：流转到下一环节
- ⬅️ **退回**：填写退回原因，提交人收到后可修改重提

审核状态在列表中以标签形式显示：待初审、部门审核中、副总工审批中、已退回。

##### 案例浏览与互动

- 列表支持按分类筛选（硬件/软件/结构/测试等）
- 入库案例支持**点赞**和**评论**功能
- 展示查阅排名（谁看过、看了多少次）
- 在线阅览同样叠加动态水印

### 6.5 绩效管理

#### 6.5.1 📋 考核模板管理

用于维护月度/年度考核表单模板：

模板示例结构：

#### 6.5.2 📅 月度绩效考核

##### 考核流程

月度考核采用**项目经理 → 直接主管 → 部门领导**三级打分机制：

```
┌──────────────────────────────────────────────────────────┐
│  ① 项目经理打分                                          │
│  - 逐项填写任务项内容、PM 打分（0-100）、PM 评价          │
│  - 提交后锁定本表，进入下一环节                            │
├──────────────────────────────────────────────────────────┤
│  ② 直接主管打分                                          │
│  - 逐项填写主管打分（0-100）、主管评价                    │
│  - 系统自动取 PM 打分和主管打分的**最大值**填入领导打分栏  │
│  - 可对高分进行预填，也可手动调整                          │
├──────────────────────────────────────────────────────────┤
│  ③ 部门领导归档                                          │
│  - 最终审核确认                                           │
│  - 可打回（仅领导有此权限），退回指定考核人重改            │
└──────────────────────────────────────────────────────────┘
```

##### 表单字段说明

| 列名 | 说明 |
|------|------|
| 大类 / 小类 | 模板中定义的考核分类层级 |
| 考核标准 | 具体的考核项名称 |
| 权重 | 该项在总分中的占比 |
| 任务项 | 被考核人当月的具体工作任务描述 |
| PM 打分 | 项目经理给出的分数（0-100） |
| 主管打分 | 直接主管给出的分数（0-100） |
| 领导打分 | 部门领导最终确认的分数（预填为 PM/主管最大值） |
| PM / 主管 / 领导评价 | 各角色的评语（多行文本） |

##### 评分联动逻辑

系统自动同步 PM 打分和主管打分到领导打分预填值：
- 当 PM 打分和主管打分都填写后，**领导打分自动取两者的最大值**
- 支持手动覆盖预填值

##### 状态流转

| 状态 | 说明 | 可操作 |
|------|------|--------|
| 考核表已创建 | 表已生成但未开始打分 | 无 |
| 待 PM 打分 | PM 尚未填写 | PM 可打分 |
| PM 已打分，待主管打分 | PM 已提交 | 主管可打分 |
| 主管已打分，待领导归档 | 主管已提交 | 领导可归档/打回 |
| 已打回 | 领导打回 | 相关考核人可重新编辑 |
| 已完成 | 领导已归档 | 任何人不可修改 |

#### 6.5.3 📊 年度绩效管理

年度考核、互评管理、我的互评任务与年终考核汇总同属年度绩效链路，合并为一个二级菜单「年度绩效管理」，下含四个三级子项：

##### 🎯 年度绩效考核

年度考核与月度考核流程完全一致（项目经理 → 主管 → 领导三级打分），区别仅在于：
- 使用**年度模板**（权重和考核标准不同）
- 考核期次为当年全年

##### 👥 互评管理

主管和项目经理专属，用于配置和管理互评人：

1. **批量配置互评人**：选择一个被考核人，指定若干同事作为其互评人
2. **查看互评提交进度**：哪些互评人已提交、哪些未提交
3. **计算互评平均分**：所有互评人分数的自动平均值

##### ✍️ 我的互评任务

主管和项目经理登录后，可以在这里看到**分配给自己的互评任务列表**：
- 待评价的同事
- 考核期次
- 状态
- 点击进入互评打分表单完成评价

##### 🏆 年终考核汇总

部门领导专属，年终自动生成：

1. **自动汇总当年月度成绩**：计算每位被考核人的全年月度平均分
2. **生成互评分**：互评平均分（来自「互评管理」子项）
3. **综合得分**：月度平均分 × 权重 + 互评分 × 权重
4. **排序**：按综合得分降序自动排序
5. **手工赋等级**：A / B / C / D（比例可按部门要求分配）

系统同时提供"强制生成年终得分"功能，确保所有人员都有最终结果。

#### 6.5.4 🔎 结果查询 / 检索

所有角色可查询考核结果：
- 支持按工号查询自己的历史考核结果
- 支持时间区间筛选
- 支持按关键词检索
- 展示：类型、期次、被考核人、汇总总分、考核结果等级、总评价、生成时间
- 数据**永久保存**，支持导出

**🗂 门户配置**（主系统门户展示的子系统卡片，数据存于 `oa_portal`）：

| 操作 | 说明 |

| **+ 新增外部系统** | 右上角直接新增外部系统门户卡（名称 / 图标 / 跳转链接 / 描述 / 状态 / 可见角色），即时生效，无需改种子 |

- **主题配色**（仅内部系统卡）：**默认**（按板块约定色）+ 8 套预设（商务蓝 / 生机绿 / 科技青 / 典雅紫 / 活力橙 / 品红 / 中国红 / 极客蓝）+ **自定义**。选定后**主系统首页该卡**（图标底座、徽章、进入链、悬停投影）与**对应子系统窗口**（顶栏、按钮、标题竖线、磁贴高亮、标签、底色，经 `applySubsystemTheme` 注入 CSS 变量）同步换肤；自定义色的深色（顶栏）与浅底（磁贴悬停）由基色按预设同规则派生（混黑 18% / 混白 93%）；选「默认」清除配置回落板块默认色（外部卡无主题）
- **自定义取色就在格子里**（v5.8）：不再有单独一行取色器——「自定义」格里的色点本身就是取色器，点格子即进入自定义并就地唤起系统取色盘，格子标签实时显示色值（如 `#0f9d58`）；未取过色时色点为彩虹圆点，取色完毕自动勾选「自定义」并写入该色值。首次取色从卡片当前生效色起步；同一弹窗内切到预设再点回来会恢复上次选的自定义色
- **编辑时的主题预选中**（v5.7）：打开编辑弹窗即按**当前生效主题**高亮——卡片已单独指定过主题就选中该预设 / 自定义色；未指定（含旧版本遗留、卡片无 `theme` 字段的数据）则选中该板块默认色（如绩效管理 → 典雅紫），与列表里的主题圆点保持一致；此时不动色板直接保存**不会**把主题钉成该预设，仍保持「跟随板块默认」。列表圆点提示也会标注「跟随板块默认」
- **可见角色**：不勾选 = 全部角色可见；勾选后仅列出角色可见。内部卡还受角色权限配置中的模块授权约束（`sysAdmin` 为超级用户，不受白名单约束）
- 内部系统卡仍由种子 `js/modules/config-portal.js` 的 `DEFAULT_PORTAL_APPS` 定义（发版后自动同步，与菜单种子同机制）；外部系统卡直接在界面上新增，数据按站点持久化
- 持久化语义同菜单管理：刷新后保留，不会被种子恢复

**🧭 子系统菜单**（各子系统内部的三级菜单树，原有能力原样保留）：

- **新增模块**：创建顶级一级模块，设置名称、图标、类型（内部/外部）
- **新增子菜单**：在已有模块下添加二级/三级子菜单
- **菜单类型**：
  - `internal`（内部）：指向系统内置页面
  - `external`（外部）：点击后在新窗口打开指定 URL
- **业务级 Actions**：为菜单项声明支持的操作权限（view/add/edit/delete/export/admin）
- **排序**：通过 order 字段控制菜单项显示顺序

**持久化语义**（`oa_menus` 为唯一事实源）：
- 菜单管理中的新增 / 删除 / 改名 / 排序均写入 localStorage，**刷新后保留**，不会被种子数据恢复
- 种子同步按「指纹闸门」执行：`DEFAULT_MODULES` 的内容哈希存于 `oa_menu_seed_hash`，仅当代码里的种子相对上次加载发生过变更（发版）时才同步一次——注入种子新增的菜单、清理种子移除的菜单，完成后刷新指纹；种子未变更时完全尊重用户的运行时数据
- **删除墓碑**（`oa_menu_deleted_keys`）：用户删掉的种子菜单 key 会记入墓碑，后续发版同步不会把它重新灌回来
- 用户自建的菜单带 `custom` 标记，种子清理时不删除；用户改过的种子菜单带 `edited` 标记，种子元数据（名称/图标/排序/actions）不覆盖
- 删除菜单会同步清理所有角色的对应 perms

| `oa_route::<子系统key>` | 各子系统窗口自己的路由（窗口隔离，互不污染） | sessionStorage |
| `oa_accounts` | 全部账号档案 | localStorage |
| `oa_depts` | 部门列表 | localStorage |
| `oa_roles` | 角色定义 + perms 权限树 | localStorage |
| `oa_menus` | 菜单结构树 | localStorage |
| `oa_menu_seed_hash` | 菜单种子指纹（种子变更时才同步一次，见 6.6.4） | localStorage |
| `oa_menu_deleted_keys` | 用户删除过的种子菜单 key 墓碑（发版同步不回灌） | localStorage |
| `oa_portal` | 主系统门户卡片配置（上架 / 排序 / 描述 / 主题配色 / 可见角色 / 新增外部系统，见 6.6.4） | localStorage |
| `oa_std` / `oa_ec_cases` | 标准库 / 案例库数据 | localStorage |
| `oa_sys_notices` | 通知公告数据 | localStorage |
| `oa_notice_read::<账号>` | 公告已读记录（按账号隔离） | localStorage |
| `oa_fav_apps::<账号>` | 我的常用应用（两级结构 {app,mod,sub}，按账号隔离） | localStorage |
| `oa_recent::<账号>` | 最近访问记录（{mod,sub,name,icon,ts}，最多 8 条，按账号隔离；v5.2 侧栏「最近访问」） | localStorage |
| `oa_pa_*` | 绩效管理相关数据 | localStorage |
| `oa_asset_spec` / `oa_asset_tpl` / `oa_asset_design` / `oa_asset_check` | 过程资产 4 个子模块 | **localStorage** |

### 7.3 数据丢失场景

| 操作 | 影响 |
|------|------|
| 关闭浏览器标签页 | sessionStorage 全部数据丢失（会话、路由等） |
| 清除浏览器缓存 | 所有存储数据清空 |
| 切换浏览器 | 数据不共享 |


## 8. 常见问题解答

### Q1：刷新页面后为什么账号还在？

系统在登录成功后会将会话信息（`oa_session`）写入 sessionStorage，每次打开页面时优先从 sessionStorage 恢复登录状态。刷新页面不会清除 sessionStorage，所以账号保持登录。

### Q2：我登录后看不到标准库/绩效管理等菜单？

菜单按角色权限动态显示。请确认你的账号角色（可点击右上角头像查看）：
- 一般人员：可查看所有模块但无新增/编辑/管理员权限
- 如需权限变更，请联系系统管理员在「系统管理 → 角色管理 → 权限配置」中为你的角色授权

### Q3：为什么有些按钮（如"新建标准"）点不动？

这些按钮受**业务级 Action 权限**控制。每个菜单项声明了具体的操作权限（view/add/edit/delete/export/admin），只有你的角色拥有对应权限时按钮才会显示或可操作。系统管理员可在权限配置弹窗中调整。

### Q4：绩效考核表提交后还能修改吗？

**不能自行修改**。一旦 PM 或主管提交打分，本表会自动锁定并流转到下一环节。如需修改，需由上级角色执行**打回**操作（仅部门领导和系统管理员有打回权限），被打回的考核表会退回到上一环节重新编辑。

### Q5：经验案例库查重是怎么实现的？

目前原型阶段的查重机制是基于**标题指纹 + 附件哈希**的前端比对：
- 标题指纹：对标题文本进行归一化处理后计算相似度
- 附件哈希：对上传文件内容计算哈希值判断是否完全重复
- 发现疑似相似时会弹出相似度提示，用户确认非重复后仍可继续提交

### Q6：PDF 在线预览的水印能去掉吗？

**不能**，水印是前端在渲染时通过 CSS 叠加的，基于「当前登录用户名 + 时间戳」动态生成，旨在防止截屏泄密。这是安全设计，确保每个查看/下载行为都可追溯。

### Q7：如何添加新的角色或修改默认权限？

步骤：
1. 登录 admin 系统管理员账号
2. 进入「系统管理 → 角色管理」
3. 点击「+ 新增角色」（自定义角色）或选中已有角色点击「权限配置」
4. 在弹窗中勾选模块/子菜单/三级菜单的访问权限
5. 同时勾选叶子节点的业务级操作权限（查看/新增/编辑等）
6. 保存后自动对所有打开系统的页面生效

### Q8：外部系统（项目管理等）的地址在哪里配置？如何新增一个外部系统？

**修改地址**：在「系统管理 → 菜单管理 → **门户配置**」tab 中，找到对应的外部系统卡片，点击「编辑」修改其**跳转链接**（保存后全用户生效）。

**新增外部系统**：在同一 tab 右上角点击「**+ 新增外部系统**」，填写名称 / 图标 / 跳转链接（须以 http:// 或 https:// 开头）/ 描述 / 运行状态 / 可见角色即可，保存后门户即时展示（按站点持久化，无需改种子）。

内部系统卡仍由源代码 `js/modules/config-portal.js` 的 `DEFAULT_PORTAL_APPS` 种子定义（发版后自动同步，见 6.6.4）。

### Q9：如何重置所有数据？

方法一（推荐）：清除浏览器 localStorage 和 localStorage

```javascript
// F12 打开浏览器控制台，输入以下命令
localStorage.clear();
sessionStorage.clear();
location.reload();
```

方法二：清除浏览器缓存后重新打开页面，所有数据会重置为代码中的种子 Mock 数据。

### Q10：待办提醒弹窗能关闭吗？

可以。点击弹窗右下角的「知道了」按钮后，本次登录期间不再自动弹出。如需再次查看，点击右上角 🔔 铃铛图标即可。

### Q11：子系统为什么在新窗口打开？能改回同窗口切换吗？

这是 v2「窗口级分离」的刻意设计：每个子系统是独立页面（`subs/<key>.html`）+ 独立样式（`css/subs/<key>.css`），形式上是一个独立站点，未来可单独打包部署；底层仍共享同一套代码、登录态与数据。若需要改回同窗口，把 `js/modules/views.js` 中 `_subAppCardHtml` 的 `openSubsystem('${mod}')` 与 `views-portal.js` 中 `openFavApp` 的 `__jumpSub(mod, sub)` 换为站内导航函数即可（壳函数已移除，需恢复 router 的 `enterSubsystem` 语义）。

### Q12：子系统窗口的样式在哪里改？

每个子系统一个独立样式文件：`css/subs/proj.css`（蓝）/ `dev.css`（绿）/ `asset.css`（青）/ `perf.css`（紫）。它们在整站 `css/style.css` **之后**加载，通过覆写 CSS 变量（`--primary` / `--headerBg` / `--iconBlue` / `--bg` / `--radius` 等）与少量局部组件实现主题差异；改样式只动对应子系统的文件，不影响其他窗口。
