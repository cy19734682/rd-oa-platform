## 1. 系统概述

**研发OA综合平台**是前卫表业工程技术研究中心自主建设的内部办公自动化综合平台，旨在解决研发过程中知识分散、标准难以检索、绩效考核流程不透明、过程资产无沉淀等痛点。平台提供**统一入口、统一账号、统一权限**的一站式工作台，覆盖研发团队日常工作的核心场景。

### 核心特点

| 特点 | 说明 |
|------|------|
| 纯前端原型 | 无后端依赖，直接用浏览器打开即可运行 |
| 权限驱动 | 菜单、按钮、数据全部按角色权限动态展示 |
| 三级审核 | 经验案例入库、绩效考核等均走标准化审批流 |
| 水印防护 | 在线预览 PDF 自动叠加「用户名+时间」动态水印 |
| 待办聚合 | 首页统一收集跨模块待办事项，右上角铃铛实时提醒 |
| 外链聚合 | 第三方业务系统通过外部子菜单统一入口 |

### 技术架构

```
前端技术栈：原生 JavaScript + HTML5 + CSS3 + SheetJS (xlsx 解析)
数据存储：  localStorage（会话级）+ localStorage（持久级）
路由方案：  自定义三级路由（module → sub → subsub）+ localStorage 持久化
```

## 2. 运行环境与启动方式

### 运行环境

| 项目 | 要求 |
|------|------|
| 浏览器 | Chrome 90+、Edge 90+、Firefox 90+、Safari 14+ |
| 操作系统 | Windows 10/11、macOS、Linux |
| Node.js（可选） | 用于启动本地静态服务器 |

### 启动方式

**方式一：直接打开（推荐原型演示）**
```
直接双击 index.html 文件，用浏览器打开即可
```

**方式二：本地静态服务器（推荐开发调试）**
```bash
# 使用 npx 启动（需 Node.js 环境）
cd rd-oa-platform
npx serve -p 3000

# 或使用 pnpm
pnpm dlx serve -p 3000
```
启动后访问 `http://localhost:3000` 即可。

 ⚠️ **注意**：通过 `file://` 协议打开时，部分浏览器（如 Chrome）的 localStorage 在不同标签页间不共享，且外链跳转可能被拦截。建议使用本地服务器方式访问。

## 3. 登录与认证

### 3.1 登录页面

打开系统后首先进入登录页面，左侧展示公司名称"前卫表业"，右侧为登录表单。

### 3.2 演示账号

系统预置了多组演示账号，点击登录页面底部的标签即可**自动填充账号密码**：

| 工号/账号 | 角色 | 默认密码 | 说明 |
|-----------|------|----------|------|
| **8001** | 一般人员 | `123456` | 普通研发人员，拥有查看和导出权限 |
| **8004** | 项目经理 | `123456` | 可对过程资产进行新增/编辑/删除 |

### 3.3 登录操作步骤

1. 在「用户名 Account」输入框中输入工号或账号
2. 在「密码 Password」输入框中输入对应密码
3. 点击「登 录」按钮
4. 登录成功后自动进入第一个有权限的模块

### 3.4 会话保持

- 登录成功后，会话信息持久化到 **sessionStorage**（`oa_session`）
- 刷新页面可自动恢复登录状态和上次浏览位置
- **关闭浏览器标签页** → 会话丢失，需重新登录
- **点击头像下拉 → 切换角色/退出登录** → 清除会话并返回登录页

### 3.5 登录拦截机制

未登录时直接访问系统内部路由会被拦截器拦截，强制跳转回登录页面，有效保护子系统入口安全。

## 5. 角色与权限体系

### 5.1 角色定义

系统内置 **5 个角色**，每个角色拥有不同的菜单和操作权限：

| 角色 | 角色编码 | 默认账号 | 权限范围摘要 |
|------|----------|----------|--------------|
| **一般人员** | `staff` | 8001 | 所有模块的**查看**和**导出**权限，标准管理员功能除外 |
| **项目经理** | `projManager` | 8004 | 在一般人员基础上，额外拥有**过程资产**模块 4 个子菜单的新增/编辑/删除权限 |
| **主管** | `supervisor` | 8005 | 在一般人员基础上，额外拥有**绩效管理**模块的模板管理、月度/年度考核编辑权限 |
| **部门领导** | `deptLeader` | 8006 | 在主管基础上，额外拥有**年终考核汇总**编辑权限、**互评管理**配置权限 |
| **系统管理员** | `sysAdmin` | admin | **超级管理员**，拥有全部模块全部权限，负责账号/角色/菜单/字典/日志管理 |

### 5.2 权限控制维度

系统采用**两级权限控制**模型：

```
┌─────────────────────────────────────┐
│  第一层：模块级权限（菜单可见性）      │
│  角色 → 模块 → 子菜单 → 三级子菜单    │
├─────────────────────────────────────┤
│  第二层：业务级操作权限（按钮可见性）  │
│  每个菜单项可声明 6 种 Action 权限：   │
│  view（查看） add（新增） edit（编辑） │
│  delete（删除） export（导出）admin（管理员）│
└─────────────────────────────────────┘
```

### 5.3 权限配置方法

仅 **系统管理员** 可配置角色权限：

1. 登录 admin 账号
2. 进入「系统管理 → 角色管理」
3. 找到目标角色，点击「权限配置」按钮
4. 在弹窗中勾选各模块/子菜单的访问权限，以及具体的操作权限（查看/新增/编辑/删除/导出/管理员）
5. 点击「💾 保存配置」生效

权限变更后，所有打开该系统的页面会自动刷新菜单，无需手动刷新浏览器。

### 5.4 内置角色与自定义角色

- **内置角色**（staff、projManager、supervisor、deptLeader、sysAdmin）：不可删除，名称/描述跟随代码更新，权限可调整
- **自定义角色**：由系统管理员在角色管理中新增，默认继承一般人员权限，可按需扩展

## 6. 功能模块详解

### 6.1 首页（平台总览）

点击顶部 Logo 或选择「🏠 首页」模块进入平台总览页面。页面按当前角色权限动态展示以下板块：

#### 6.1.1 全局数据看板（上方面板）

以卡片形式展示平台核心数据指标，点击卡片可直接跳转对应模块：

| 卡片 | 说明 |
|------|------|
| 👥 启用账号 | 当前系统中状态为启用的账号总数 |
| 📚 现行标准 | 标准库中状态为"现行"的标准数量 |
| 💡 入库案例 | 经验案例库中已完成三级审核的案例数量 |
| 📈 进行中考核 | 尚未完成的绩效考核表数量 |
| 📐 过程资产 | 开发规范+文档模板+设计规范+评审Checklist 的总量 |
| ⚠️ 待处理事项 | 待审核案例 + 待打分考核表的合计数量 |

 权限不足的数据卡片会自动隐藏，例如只有系统管理员才能看到"启用账号"卡片。

#### 6.1.2 绩效考核概览

用进度条展示绩效考核状态分布，包括：待自评、待主管打分、待PM打分、待领导归档、已完成。同时列出"我的考核表"和"最近考核结果"。

#### 6.1.3 第三方系统快捷入口

聚合了所有**外部类型**的子菜单，以卡片形式展示，点击可在新窗口打开对应外部系统。

#### 6.1.4 我的待办

按当前角色聚合跨模块待办事项，每条待办包含图标、标题、描述和快捷跳转：

| 角色 | 待办来源 |
|------|----------|
| 一般人员 | 我的考核表进度、我提交的案例审核状态 |
| 主管 | 下属的考核表（待主管打分） |
| 项目经理 | 下属/相关人员的考核表（待PM打分） |
| 部门领导 | 下属的考核表（待领导归档）、待审核案例 |
| 系统管理员 | 停用账号提醒 |

 登录成功后会自动弹窗提醒当前用户的待办清单，右上角🔔铃铛角标实时显示待办数量。

#### 6.1.5 最近动态（系统日志）

展示平台最近的操作日志，包括登录、业务操作、安全审计等，以相对时间格式显示（如"10分钟前"、"2小时前"）。

#### 6.1.6 知识速览

三列布局：
- **📚 最新标准**：标准库中按创建时间倒序的最新标准
- **💡 热门案例**：经验案例库中按浏览量排序的热门入库案例
- **📐 最近资产**：过程资产各子模块中最近更新的文档

### 6.3 研发公共

研发公共模块是平台的核心知识库，包含**标准库**、**经验案例库**以及外部工具入口。

#### 6.3.1 📚 标准库

##### 功能概览

 看板 · 智能检索 · 多维度筛选 · 在线阅览（动态水印）· 版本并存 · 标准维护（新建/升级/废止）

##### 标准状态看板

进入标准库首页，顶部展示统计看板：
- 各级别标准数量：国标 312、行标 168、团标 45、地标 22、国际 18
- 归口组织分布：中燃协 240、住建部 156、工程建设协会 89、其他 80
- 动态提醒：近1月上新 5 条、即将废止 2 条

##### 标准检索

1. 在搜索框输入关键词（支持名称、编号、摘要模糊匹配）
2. 点击「搜索」按钮或回车触发检索
3. 支持按级别、性质、领域等维度进行筛选
4. 搜索结果列表展示：标准号、中文名称、级别、性质、状态、实施日期

##### 在线预览与下载

- 点击「预览/下载」按钮打开在线阅读器
- 自动叠加 **「当前用户名 + 时间」动态水印**，防止截屏泄密
- 支持翻页、放大、缩小、全屏浏览
- 下载 PDF 时服务端自动写入水印

##### 标准维护（需标准管理员权限）

点击「+ 新建标准」按钮打开表单，填写：
- 标准编号、中文名称、英文名称
- 级别（国标/行标/团标/地标/国际）、性质（强制/推荐）
- 所属领域、归口组织、起草单位
- 发布日期、实施日期
- PDF 主文件、Word 附件上传

**升级新版本**：对已有标准点击「升级」，上传新版本文件；保存后老版本自动留存并记录替代关系。

**废止标准**：点击「废止」将状态标记为已作废，系统会向订阅人员推送动态提醒。

##### 版本并存机制

同一标准的不同版本可同时存在，通过「查看旧版」按钮查看历史版本，旧版状态标记为「已作废」或「已被代替」。

#### 6.3.2 💡 经验案例库

##### 功能概览

 五段式经验沉淀 · 三级审核入库 · 点赞评论 · 查阅排名 · 动态水印

##### 五段式提交

提交经验案例时，系统引导完成以下五个必填段落：

| 段落 | 说明 | 占位提示 |
|------|------|----------|
| ① 问题描述 | 描述现象与影响范围 | "如：超声波燃气表计量漂移问题" |
| ② 问题分析过程 | 排查路径 | "逐步缩小范围的分析过程" |
| ③ 问题根因 | 根本原因 | "定位到的最终根因" |
| ④ 解决方法 | 解决方案与验证 | "实施的修复措施及验证结果" |
| ⑤ 经验总结 | 可复用的经验 | "对类似问题的预防建议" |

附加信息：标题、产品型号、关键字标签、附件上传。

 ⚠️ **敏感脱敏提示**：提交前请对正文与附件中的客户信息、用户信息、数量信息等进行脱敏处理，主管初审会复核把关。

##### 自动查重

提交时系统自动按「标题指纹 + 附件哈希」进行查重，发现疑似相似案例会提示相似度百分比，用户确认非重复后可继续提交。

##### 三级审核流程

```
提交 → ① 直接主管初审 → ② 部门领导审核 → ③ 副总工审批 → 入库
         │                │                │
         └── 可退回重提   └── 可退回重提   └── 可退回重提
```

每个审核环节都可：
- ✅ **通过**：流转到下一环节
- ⬅️ **退回**：填写退回原因，提交人收到后可修改重提

审核状态在列表中以标签形式显示：待初审、部门审核中、副总工审批中、已退回。

##### 案例浏览与互动

- 列表支持按分类筛选（硬件/软件/结构/测试等）
- 入库案例支持**点赞**和**评论**功能
- 展示查阅排名（谁看过、看了多少次）
- 在线阅览同样叠加动态水印

### 6.4 过程资产

过程资产模块用于沉淀研发过程中可复用的文档资源，包含 4 个子模块：

| 子模块 | 图标 | 说明 |
|--------|------|------|
| **📐 开发规范** | 结构设计、接口定义、编码风格等开发规范文档 |
| **📄 文档模板** | 可复用的文档模板，覆盖产品/研发/测试/运维/管理全角色 |

| **✅ 评审 Checklist** | 研发、测试、需求、发布各环节评审检查项模板 |

每个子模块功能统一：
- **列表页**：展示资产标题、分类、更新时间、浏览量
- **新增**（需 add 权限）：填写标题、分类、正文（支持 Markdown 格式）、附件
- **编辑/删除**（需 edit/delete 权限）：对已有资产进行维护
- **查看详情**：Markdown 渲染预览，支持代码块、表格、列表、勾选框等语法
- **搜索**：按标题/关键字/分类快速检索

 💡 **权限提示**：一般人员拥有 view + export，项目经理额外拥有 add + edit + delete。

### 6.5 绩效管理

绩效管理模块是平台中流程最复杂的模块之一，支持**月度考核**、**年度考核**、**互评管理**和**年终汇总**。

#### 6.5.1 📋 考核模板管理

用于维护月度/年度考核表单模板：

- 模板结构：大类 → 小类 → 考核标准 → 权重
- 每个小类下可配置多个考核标准项
- 支持创建多个版本，自动保存历史版本
- 每个版本可标记为"启用"状态，当前只有最新启用版本生效

模板示例结构：
```
├── 大类：工作业绩
│   ├── 小类：项目完成情况（权重 40%）
│   │   ├── 考核标准：按时交付率
│   │   └── 考核标准：交付质量
│   └── 小类：文档编写（权重 20%）
├── 大类：工作能力
│   └── ...
└── 大类：工作态度
    └── ...
```

#### 6.5.2 👥 考核人员库

部门领导维护考核人员信息：
- 工号、姓名、属性（员工/主管/项目经理）
- 部门小组
- 直接主管、部门领导

 人员库是绩效考核的基础数据，主管和项目经理会根据此表确定自己要打分的下属范围。

#### 6.5.3 📅 月度绩效考核

##### 考核流程

月度考核采用**项目经理 → 直接主管 → 部门领导**三级打分机制：

```
┌──────────────────────────────────────────────────────────┐
│  ① 项目经理打分                                          │
│  - 逐项填写任务项内容、PM 打分（0-100）、PM 评价          │
│  - 提交后锁定本表，进入下一环节                            │
├──────────────────────────────────────────────────────────┤
│  ② 直接主管打分                                          │
│  - 逐项填写主管打分（0-100）、主管评价                    │
│  - 系统自动取 PM 打分和主管打分的**最大值**填入领导打分栏  │
│  - 可对高分进行预填，也可手动调整                          │
├──────────────────────────────────────────────────────────┤
│  ③ 部门领导归档                                          │
│  - 最终审核确认                                           │
│  - 可打回（仅领导有此权限），退回指定考核人重改            │
└──────────────────────────────────────────────────────────┘
```

##### 表单字段说明

| 列名 | 说明 |
|------|------|
| 大类 / 小类 | 模板中定义的考核分类层级 |
| 考核标准 | 具体的考核项名称 |
| 权重 | 该项在总分中的占比 |
| 任务项 | 被考核人当月的具体工作任务描述 |
| PM 打分 | 项目经理给出的分数（0-100） |
| 主管打分 | 直接主管给出的分数（0-100） |
| 领导打分 | 部门领导最终确认的分数（预填为 PM/主管最大值） |
| PM / 主管 / 领导评价 | 各角色的评语（多行文本） |

##### 评分联动逻辑

系统自动同步 PM 打分和主管打分到领导打分预填值：
- 当 PM 打分和主管打分都填写后，**领导打分自动取两者的最大值**
- 支持手动覆盖预填值

##### 状态流转

| 状态 | 说明 | 可操作 |
|------|------|--------|
| 考核表已创建 | 表已生成但未开始打分 | 无 |
| 待 PM 打分 | PM 尚未填写 | PM 可打分 |
| PM 已打分，待主管打分 | PM 已提交 | 主管可打分 |
| 主管已打分，待领导归档 | 主管已提交 | 领导可归档/打回 |
| 已打回 | 领导打回 | 相关考核人可重新编辑 |
| 已完成 | 领导已归档 | 任何人不可修改 |

#### 6.5.4 🎯 年度绩效考核

年度考核与月度考核流程完全一致（项目经理 → 主管 → 领导三级打分），区别仅在于：
- 使用**年度模板**（权重和考核标准不同）
- 考核期次为当年全年

#### 6.5.5 👥 互评管理

主管和项目经理专属，用于配置和管理互评人：

1. **批量配置互评人**：选择一个被考核人，指定若干同事作为其互评人
2. **查看互评提交进度**：哪些互评人已提交、哪些未提交
3. **计算互评平均分**：所有互评人分数的自动平均值

#### 6.5.6 ✍️ 我的互评任务

主管和项目经理登录后，可以在这里看到**分配给自己的互评任务列表**：
- 待评价的同事
- 考核期次
- 状态
- 点击进入互评打分表单完成评价

#### 6.5.7 🏆 年终考核汇总

部门领导专属，年终自动生成：

1. **自动汇总当年月度成绩**：计算每位被考核人的全年月度平均分
2. **生成互评分**：互评平均分（来自互评管理模块）
3. **综合得分**：月度平均分 × 权重 + 互评分 × 权重
4. **排序**：按综合得分降序自动排序
5. **手工赋等级**：A / B / C / D（比例可按部门要求分配）

 系统同时提供"强制生成年终得分"功能，确保所有人员都有最终结果。

#### 6.5.8 🔎 结果查询 / 检索

所有角色可查询考核结果：
- 支持按工号查询自己的历史考核结果
- 支持时间区间筛选
- 支持按关键词检索
- 展示：类型、期次、被考核人、汇总总分、考核结果等级、总评价、生成时间
- 数据**永久保存**，支持导出

## 7. 数据存储说明

本原型系统的数据存储策略如下：

### 7.1 存储位置

| 存储位置 | 生命周期 | 存储内容 |
|----------|----------|----------|
| **sessionStorage** | 关闭浏览器标签页即清除 | 会话信息、路由信息|
| **localStorage** | 持久化保存，关闭浏览器不丢失 | 账号数据、部门数据、角色/权限、菜单结构、案例库、考核表、字典、 过程资产 |

### 7.2 关键存储 Key 一览

| Key | 说明 | 位置 |
|-----|------|------|
| `oa_session` | 当前登录会话（uid、role、time） | sessionStorage |
| `oa_accounts` | 全部账号档案 | localStorage |
| `oa_depts` | 部门列表 | localStorage |
| `oa_roles` | 角色定义 + perms 权限树 | localStorage |
| `oa_menus` | 菜单结构树 | localStorage |
| `oa_std` / `oa_ec_cases` | 标准库 / 案例库数据 | localStorage |
| `oa_pa_*` | 绩效管理相关数据 | localStorage |
| `oa_asset_spec` / `oa_asset_tpl` / `oa_asset_design` / `oa_asset_check` | 过程资产 4 个子模块 | **localStorage** |

### 7.3 数据丢失场景

| 操作 | 影响 |
|------|------|
| 关闭浏览器标签页 | sessionStorage 全部数据丢失（会话、路由等） |
| 清除浏览器缓存 | 所有存储数据清空 |
| 切换浏览器 | 数据不共享 |


## 8. 常见问题解答

### Q1：刷新页面后为什么账号还在？

系统在登录成功后会将会话信息（`oa_session`）写入 sessionStorage，每次打开页面时优先从 sessionStorage 恢复登录状态。刷新页面不会清除 sessionStorage，所以账号保持登录。

### Q2：我登录后看不到标准库/绩效管理等菜单？

菜单按角色权限动态显示。请确认你的账号角色（可点击右上角头像查看）：
- 一般人员：可查看所有模块但无新增/编辑/管理员权限
- 如需权限变更，请联系系统管理员在「系统管理 → 角色管理 → 权限配置」中为你的角色授权

### Q3：为什么有些按钮（如"新建标准"）点不动？

这些按钮受**业务级 Action 权限**控制。每个菜单项声明了具体的操作权限（view/add/edit/delete/export/admin），只有你的角色拥有对应权限时按钮才会显示或可操作。系统管理员可在权限配置弹窗中调整。

### Q4：绩效考核表提交后还能修改吗？

**不能自行修改**。一旦 PM 或主管提交打分，本表会自动锁定并流转到下一环节。如需修改，需由上级角色执行**打回**操作（仅部门领导和系统管理员有打回权限），被打回的考核表会退回到上一环节重新编辑。

### Q5：经验案例库查重是怎么实现的？

目前原型阶段的查重机制是基于**标题指纹 + 附件哈希**的前端比对：
- 标题指纹：对标题文本进行归一化处理后计算相似度
- 附件哈希：对上传文件内容计算哈希值判断是否完全重复
- 发现疑似相似时会弹出相似度提示，用户确认非重复后仍可继续提交

### Q6：PDF 在线预览的水印能去掉吗？

**不能**，水印是前端在渲染时通过 CSS 叠加的，基于「当前登录用户名 + 时间戳」动态生成，旨在防止截屏泄密。这是安全设计，确保每个查看/下载行为都可追溯。

### Q7：如何添加新的角色或修改默认权限？

步骤：
1. 登录 admin 系统管理员账号
2. 进入「系统管理 → 角色管理」
3. 点击「+ 新增角色」（自定义角色）或选中已有角色点击「权限配置」
4. 在弹窗中勾选模块/子菜单/三级菜单的访问权限
5. 同时勾选叶子节点的业务级操作权限（查看/新增/编辑等）
6. 保存后自动对所有打开系统的页面生效

### Q8：外部系统（项目管理等）的地址在哪里配置？

在「系统管理 → 菜单管理」中，找到对应的外部子菜单项，修改其 `url` 字段即可。也可在源代码 `js/modules/config.js` 的 `DEFAULT_MODULES` 中直接修改种子数据。

### Q9：如何重置所有数据？

方法一（推荐）：清除浏览器 localStorage 和 localStorage

```javascript
// F12 打开浏览器控制台，输入以下命令
localStorage.clear();
sessionStorage.clear();
location.reload();
```

方法二：清除浏览器缓存后重新打开页面，所有数据会重置为代码中的种子 Mock 数据。

### Q10：待办提醒弹窗能关闭吗？

可以。点击弹窗右下角的「知道了」按钮后，本次登录期间不再自动弹出。如需再次查看，点击右上角 🔔 铃铛图标即可。
